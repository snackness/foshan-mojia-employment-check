# 上线前核查清单

## 一、事实与证据

- [ ] R-01 至 R-07 每一项都有内部证据编号、原文件、取得日期和持有人记录；
- [ ] 核对原文件的上下文，避免只取对自己有利的片段；
- [ ] 2 万元拆分金额有完整协议或支付记录支持，否则继续标为待核实；
- [ ] 3 年竞业只写协议样本可见内容，返还和补偿部分若无完整条款则标为待核实；
- [ ] 欠薪、降薪、996、追加目标及会议评价均未写成行政或司法确认事实；
- [x] 页面未出现“黑心、骗子、诈骗、独裁、无能、愚蠢、一定违法”等标签。

## 二、隐私与商业秘密

- [x] 搜索并确认无员工、老板、HR、客户或供应商姓名、别名和账号；
- [x] 除本站专用更正邮箱外，无个人电话、邮箱、头像、声音、身份证、银行卡、签名、住址、行踪或具体部门；
- [x] 无原始合同、录音、聊天、工资流水、客户清单、图纸、代码、价格或未公开项目数据；
- [x] 检查 PDF 元数据，Author、Creator、LastModifiedBy 不含真实身份；
- [x] 检查 Git 历史，确认从未提交 `private-evidence/` 或其他原件；
- [ ] GitHub 账号名、头像、个人主页和提交邮箱不会暴露不希望关联的真实身份。

## 三、企业核验与回应

- [ ] 使用企业公开招聘联系方式、工商登记联系方式或其他官方渠道发送核验通知；
- [ ] 保存发送时间、送达状态和完整通知，不公开联系人个人信息；
- [ ] 给予合理答复时间，例如 5 至 7 个工作日；
- [ ] 未回复只记录“截至某日未收到回复”，不得视为默认承认；
- [ ] 如收到可核验反证，在上线前更正；如存在争议，并列双方具体说法；
- [x] 在 `assets/site-config.js` 填写专用更正邮箱。

## 四、GitHub 与发布

- [ ] 使用公开仓库；确认 Pages 网站及提交历史均会公开；
- [ ] GitHub 邮箱设置已启用隐私邮箱，本地提交使用 GitHub `noreply` 邮箱；
- [ ] 仓库关闭 Issues、Discussions、Wiki、Projects 等不需要的公开互动功能；
- [ ] Settings → Pages 的 Source 选择 GitHub Actions；
- [x] Actions 仅有 `contents: read`、`pages: write`、`id-token: write` 权限；
- [ ] 部署后检查首页、移动端、下载链接、官方法源链接和 404 页面；
- [ ] 开启 Enforce HTTPS；如使用自定义域名，先验证域名再配置 DNS。
